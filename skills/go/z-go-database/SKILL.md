# Go database access

Use explicit SQL for new queries under this convention. Preserve existing database abstractions that satisfy the contract.

## Library choice

| | `database/sql` | `sqlx` | `pgx` |
|---|---|---|---|
| Multi-database | yes | yes | no |
| Struct scanning | manual `Scan` | `StructScan` / `Select` | `pgx.RowToStructByName`, or generated by `sqlc` |
| PG-specific (COPY, LISTEN, arrays) | no | no | yes |
| Performance | benchmark representative queries | thin wrapper over database/sql | benchmark native and generated-query paths |

Use pgx for PostgreSQL-specific features. Pair it with [[z-go-sqlc]] for generated static queries.

Use `database/sql` or sqlx when the service needs its driver ecosystem. SQL dialect portability still requires compatible queries.

## Parameterized queries

```go
// bad — SQL injection
query := fmt.Sprintf("SELECT * FROM users WHERE email = '%s'", email)

// good — pgx, parameterized
var u User
err := pool.QueryRow(ctx, "SELECT id, name FROM users WHERE email = $1", email).
    Scan(&u.ID, &u.Name)
```

Use generated queries when the project has them. Parameter binding also applies to handwritten SQL.

Dynamic `IN`: pgx encodes a Go slice as a native Postgres array, so pass it
straight through — no query-rewriting helper needed:

```go
rows, err := pool.Query(ctx, "SELECT * FROM users WHERE id = ANY($1)", ids)
```

(`sqlx` lacks native array support and needs `sqlx.In` + `db.Rebind` to expand
a slice into placeholders — only relevant if you're on the `sqlx` path.)

Select sort columns from a fixed mapping. Bound parameters apply to values and cannot select column identifiers.

## NULLable columns

`sqlc` generates the scan-safe type for a NULLable column automatically
(pointer or `pgtype.X`, depending on `sqlc.yaml`) — see [[z-go-sqlc]]. Mapping
by hand, use pointer fields — they scan correctly and marshal to JSON `null`:

```go
type User struct {
    ID        int64
    Name      string
    DeletedAt *time.Time // NULL-safe
    Bio       *string
}
```

Avoid `sql.NullString` / `sql.NullTime` — `Valid bool` leaks persistence into domain types.

## Error handling

```go
var u User
err := pool.QueryRow(ctx, "SELECT id, name FROM users WHERE id = $1", id).
    Scan(&u.ID, &u.Name)
if errors.Is(err, pgx.ErrNoRows) {
    return nil, ErrUserNotFound // translate to domain sentinel
}
if err != nil {
    return nil, fmt.Errorf("get user %s: %w", id, err)
}
```

Close query rows. Inspect `rows.Err()` after iteration. Use `Exec` when the statement returns no rows. Use `Query` or `QueryRow` for writes with `RETURNING`.

Map PostgreSQL `23505` to the relevant unique-key conflict. Retry the whole transaction on `40001` when replay is safe. Propagate caller cancellation.

## Transactions

```go
tx, err := pool.BeginTx(ctx, pgx.TxOptions{})
if err != nil {
    return fmt.Errorf("begin tx: %w", err)
}
defer func() { _ = tx.Rollback(ctx) }()

// ... operations on tx ...

if err = tx.Commit(ctx); err != nil {
    return fmt.Errorf("commit: %w", err)
}
```

Arrange rollback for every unfinished transaction. After a successful commit, ignore the expected closed-transaction result.

Choose a bounded cleanup context if the request can expire before rollback. A canceled context alone cannot roll back a pgx transaction.

### Isolation levels

```go
tx, err := pool.BeginTx(ctx, pgx.TxOptions{
    IsoLevel: pgx.Serializable,
})
```

Choose isolation from the invariant and concurrent operations. For SQLSTATE `40001`, retry the whole transaction within a bounded policy. Keep external side effects out of retryable work.

### SELECT FOR UPDATE

```go
var o Order
err := tx.QueryRow(ctx, "SELECT id, status FROM orders WHERE id = $1 FOR UPDATE", id).
    Scan(&o.ID, &o.Status)
```

`FOR UPDATE` locks the selected row until transaction end. Use `NOWAIT` when lock contention must return an error immediately.

## Connection pool

```go
cfg, err := pgxpool.ParseConfig(dsn)
if err != nil {
    return nil, fmt.Errorf("parse pool config: %w", err)
}
cfg.MaxConns = 25
cfg.MinConns = 5
cfg.MaxConnLifetime = time.Hour
cfg.MaxConnIdleTime = 30 * time.Minute

pool, err := pgxpool.NewWithConfig(ctx, cfg)
```

Budget connections across all replicas, jobs, migrations, and administrative clients. Leave server headroom and measure pool waits.

For `database/sql` and sqlx, configure `SetMaxOpenConns`, `SetMaxIdleConns`, `SetConnMaxLifetime`, and `SetConnMaxIdleTime` as needed.

## Migrations

Use the project's migration runner and review schema changes as migrations. See [[z-go-goose]].
Alternatives: `golang-migrate` (CLI + library) for non-Postgres databases, `Atlas`
(declarative + drift detection) for schema-as-state. Files go in source control.

Prefer running migrations from CI/CD over application startup. A
startup-gated migration behind an explicit opt-in env flag (e.g.
`RUN_MIGRATIONS_ON_STARTUP`, defaulting to a safe choice) is an accepted
pattern here, not a violation — gate it, don't run it unconditionally.

## Do not

- Interpolate user input into SQL — always parameterize.
- Discard the rows returned by a statement with `RETURNING`.
- Omit `rows.Close()` or `rows.Err()` — silent leaks and partial results.
- Drop the caller's context. Use the context-aware database method.
- Add database-side effects without documenting ownership and transaction behavior.
- Change schemas from application handlers. Apply schema changes through migrations.
- Run migrations unconditionally from `main()` — gate behind an explicit
  opt-in flag, or run from CI/CD.
