# Edit Russian technical prose

## Select terminology

Preserve canonical product names, identifiers, and established technical terms. Use the [bilingual glossary](references/terminology.md) for domain-specific choices.

| Context | Examples |
|---|---|
| Technical terms and product names | `connection pooling`, `DPI`, `PgBouncer`, `Kubernetes` |
| Russian legal and payment terms | 152-ФЗ, СБП, ОФД, Роскомнадзор |
| Established Russian usage | горутина, микросервис, замедление |
| Informal register | бэкенд, хендлер, деплой |

Match the requested register. Keep source code, commands, flags, and filenames exact.

## Edit for the intended reader

1. Open with the claim or practical constraint. Use a short summary when the venue supports it.
2. Give each paragraph one purpose. Name the condition under which an observation holds.
3. Number actual steps or attempts. Fence code examples and use inline code for identifiers.
4. Replace bureaucratic phrases such as «осуществлять» with a specific verb.
5. Remove stock openings, exaggerated contrasts, and calls to action that add no information.
6. Keep useful qualifications and concrete comparisons. A wording pattern alone cannot identify the author.

## Check sensitive claims

Identify the jurisdiction and date before stating a legal obligation or penalty. Check the primary text.
Attribute interpretations and distinguish them from statutory language. Use [the register guide](references/register.md) for source conventions.

## Check the result

Check terms against the glossary and the surrounding document.
Trace each factual claim to a primary source or a stated first-hand observation.
