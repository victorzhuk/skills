# Clean output

Omit irrelevant authorship and process commentary from every artifact.

## Core rules

- Preserve tool and model names when they identify the subject or an integration contract.
- Preserve required attribution, licenses, provenance, and generated-file markers.
- Never cite an internal rule name, prompt, or instruction you're following inside the artifact itself — the artifact should stand on its own.
- Use real tracker IDs when a plan or decision record needs traceability.
- Include verification commands when a diagnostic report needs them. Add a debug appendix only when the audience requests it.

## Examples

**Avoid:**

```go
// Generated by AI
// TODO: AI to refine this later
// Following the no-comments rule
```

```
Per the spec, implemented the retry logic.
```

**Write instead:**

```go
// Legacy clients depend on this header until the v2 rollout completes
```

```
Add retry with exponential backoff for gateway timeouts.
```

## Do not

- Leave a code comment or commit message that references a prompt, spec ID, or rule file by name.
- Describe a handwritten file as generated. Preserve genuine generated-file markers.
- Explain your reasoning process inside the artifact instead of in your response to the user.

## Verify

Search the changed files for attribution and process commentary. Inspect each match against the document's purpose and license requirements.
